# Reproducibility and provenance

## Version lineage

| Stage | Rows | Purpose |
|---|---:|---|
| `data/interim/TF_PWM_chart_1.tsv` | 5,384 | Retained MMseqs2-derived identity/homology assignments before family and model annotations. |
| `data/releases/TF_PWM_chart_pre_hocomoco.tsv` | 5,384 | Original 2025 table after family, ModCRE, AlphaFold-derived model attachment and invalid-model filtering. |
| `data/releases/TF_PWM_chart_final.tsv` | 5,417 | 2026 HOCOMOCO v11 update with the evidence hierarchy enforced. |

The HOCOMOCO update has been rerun from the pre-HOCOMOCO table and the included HOCOMOCO annotation file. Both the final table and audit trail match the deposited files cell-for-cell.

## What can be reproduced

- HOCOMOCO aggregation by UniProt accession.
- Addition or upgrade of HOCOMOCO-linked identical PWMs.
- Addition of 33 HOCOMOCO-only TFs.
- Evidence-hierarchy enforcement and summary columns.
- Structural-model log parsing, deduplication and invalid-model filtering from the retained logs.
- Release-level row, uniqueness, hierarchy and count checks.

## Historical limitation

The raw `TF_sequences.comparison` file created by the original MMseqs2 run was not archived, and the exact query/reference FASTA files used on the original HPC system are not deposited. Therefore the original homology matches and their threshold assignments cannot be regenerated byte-for-byte.

To avoid overstating reproducibility:

- the observed homology-stage output is retained in `data/interim/TF_PWM_chart_1.tsv`;
- the refactored scripts specify the MMseqs2 output schema and identity units explicitly;
- the homology-generation script is provided for future reruns, but its output is not claimed to be identical to the historical table without the original inputs and software environment.

## Threshold interpretation

The 70% and 50% cutoffs are project-specific operating thresholds. They should not be presented as universal TF-family-independent boundaries. The final table retains all unique model IDs qualifying within a tier rather than claiming that every value is a single nearest-neighbour assignment.

## Model-log notes

The raw logs contain repeated `DONE` records. Processing scripts deduplicate model names before joining them into a table cell. Entries in the supplied `wrong_model_modcre.txt` and `wrong_model_af3.txt` lists are excluded. The final release contains none of those invalid model names.
